ゲームの中身は 2 つの wasm モジュールで、どちらも `wasm/` の Rust を wasm32
にビルドしたものです。 ページ (`web/client/lib/graph_go/`)
はそれを読み込んでつなぎ、盤を描くだけで、ルールの判断はしません。

## エンジン (`engine.wasm`)

- **`play`** — 現在の盤面に次の 1 手を置いたとき何が起きるか。 合法か
  (だめなら「石がある」「コウ」「自殺手」)、取られる石、コウの禁止点、アタリになった相手の石、次の盤面を返す。
- **`regions`** — 空点が n
  個以上つながった部分を、周りの石ごと**部分グラフ**として取り出す。
  部分グラフは 0 から番号を振り直し、各点が元の盤のどの点かも持っている。
- **`evaluate`** — `regions` の部分グラフをそれぞれ CPU モジュールの `judge`
  に投げ、黒白どちらの地かを判定させて数える。 n
  未満の小さな領域は、エンジン自身が「片方の色だけに接していればその色」で決める。

エンジンは `cpu.judge` を **import** していて、ページがそれを CPU モジュールの
export につなぎます。 つまり「部分グラフを CPU に投げる」のはエンジン自身です。

## CPU (`cpu.wasm`)

- **`judge`** — 部分グラフの空点ごとに、近い方の色 (空点だけを通った距離)
  を数える。6 割以上を占めた色の地とし、どちらも届かなければ誰の地でもない。
- **`genmove`** — 対局で CPU
  が打つ手。原始モンテカルロで、候補手ごとにランダムな終局までの試合
  (プレイアウト) を打ち、勝率の最も高い手を選ぶ。
  自分の眼は埋めない。相手がパスした直後は、今の盤面で勝っていればパスを返して終局させる。
- **`solve`** —
  詰碁の読み。ある石の連を取れるかどうかを、決められた手数まで読み切る
  (「詰碁のしくみ」)。

CPU はエンジンと同じルールのコード (`graph-go-core`)
をリンクしているので、プレイアウトも読みも同じルールで打ちます。

## 呼び出し方

どちらのモジュールも、JSON を受け取って JSON を返します。

1. `alloc(len)` で確保したメモリにリクエストの JSON を書く
2. `play(ptr, len)` などを呼ぶと、返り値がレスポンスの長さ
3. `result_ptr()` からその長さ分を読む

失敗は trap ではなく `{"error": "..."}`
で返るので、変なリクエストでもインスタンスは死にません。 色は `0` 空 / `1` 黒 /
`2` 白、着手の `null` はパスです。

```json
{
  "graph": { "nodeCount": 3, "edges": [[0, 1], [1, 2]] },
  "stones": [0, 2, 0],
  "color": 1,
  "node": 0
}
```
