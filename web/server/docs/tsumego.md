詰碁はどれも「この石を取れるか」の問題です。

- **黒先・取る** — 青で囲んだ白の連を取れば正解。
- **白先・逃げる** — 黒がもう取れなくなれば正解。

## CPU の読み (`solve`)

決められた手数 (読みの深さ) までの手を、双方とも最善で読み切ります。
読む手は、人が石の取り合いを読むときと同じく絞っています。

- **攻める側** — 狙う連の呼吸点。呼吸点が 2 つ以下なら、その隣の点も
  (ゲタはそこに打つ)。
- **守る側** — 狙われた連の呼吸点、取れそうな (呼吸点が 2 つ以下の)
  相手の石の呼吸点、それにパス。取れそうな石は、狙われた連に接するものだけでなく、その呼吸点の隣にある味方の連に接するものも数えます
  (取って味方とつながれば逃げ道になるため)。

攻める側は、深さ以内に取れると読み切れたときだけ「取れる」とします。
呼吸点が多すぎて深さ以内に詰められない連は、その場で「逃げ切り」です。

あなたが打つたびに、CPU は相手側としてこの読みを走らせます。

- 取る問題では、白が最善の受けを打ちます。白を取れたら正解。
  白がもう助からないときは、打てる手をすべて試して一番長く粘る手
  (黒に最も多くの手数をかけさせる手)
  を打ちます。並んだら、石を取る手、呼吸点を多く残す手、連を大きくする手の順に選びます。
- 逃げる問題で、黒がもう取れないと読めたら正解。まだ取れるなら、最も早く取れる追い方をしてきます。

間違えた手を打っても「不正解」にはなりません。CPU
がその手に応じるので、そのまま打ち続けられます
(逃げる問題で白が取られたときだけは、そこで終わり)。行き詰まったら「やり直す」で最初の局面に戻ります。

「ヒント」は、打てる手を一つずつ試し、打った後に CPU
が相手側で読む結果が目的どおりになる手を示します。取る問題では、その中で最も早く取れる手です。

## 続きを検証

解き終わったら「続きを検証」で、その局面から黒白どちらの手も自由に打てます。

- 打つたびに、手番側から読んだ結果 (黒が深さ以内に取れるか) と、読みの最善手
  (青い印) が出ます。
- 「CPU
  が打つ」は手番側の最善手を打ちます。押し続けると読み筋を順にたどれます。黒が取れない局面では、黒は狙う連の呼吸点を最も減らす手を打つので、どう追っても逃げられる理由が見えます。
- 「待った」は 1 手ずつ戻ります。問題中に打った手まで戻れます。

## 問題の作り方

問題はランダムに石を置いた局面から、読みで次の条件を満たすものだけを選んでいます
(`tools/gen_tsumego.ts`)。

- 先に打てば目的を達成できるが、パスすると相手に先を越される (急場である)
- 正解の初手がちょうど 1 つ
- 取る問題は、黒が 3 手以上かかる (ただのアタリではない)

どの問題もこの条件をテスト (`wasm/graph_go_test.ts`) で確かめています。
